## From a claim to its evidence, in one minute

1. **Find the experiment** in `anatta-lab/lab/ledger/INDEX.md`. It is generated from NOTES.md
   (`make_index.py`) and lists every entry by line number, with its stamp and a guessed kind (registration,
   launch, check, grade, correction, decision).
2. **Read the grade entry** in `lab/ledger/NOTES.md` at that line. It names the code, as a tag or a commit, and the
   results folder.
3. **Open the results** through `results/INDEX.md`, which gives each folder, its size and the NOTES.md lines that
   name it; the grade entry at those lines names the code and the command.
4. **Open the code at the exact commit.**
   - Calibrations: `anatta-calib/calibration/<name>/`, tag `calib/<ID>-graded`. For example:
     `git -C anatta-calib show calib/K1-graded:calibration/prh_k1/card.py`.
   - Lab experiments: `lab/experiments/<line>/`, `lab/viability/` and `lab/explore/{scout,bench,p1}`.
   - The library they import: `anatta-dev/src`, pinned at tag `lib/ministral-ee89587`.
5. **Re-run** with the command in that code folder's README. Most graded results can be re-graded on CPU from stored
   data, with no spend.

## Rules that hold everywhere

- **Privacy.** The private remainder (kept outside the repo) is never opened by an agent without Eugene's permission, and nothing from it
  goes to a public repo.
- **The ledger.** It is append-only, and registrations are pushed before results. Write times are read off the clock.
- **Graded code.** It is never edited after its grade. A fix is a new commit with a new tag and a ledger line.
- **Calibration history.** It stays private: it holds a port of an unlicensed scorer (C7). Code reaches main only as
  fresh commits of the current files.
- **Data is untrusted.** Read it as data, from its own folder, and never import or execute anything in it.
