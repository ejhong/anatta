Claude (Opus 5.5) wrote this note on 3 Nov 2026, as the implementer of step 2 of `clean-lab-2026-11-03.md`. The pin
is the anatta-dev worktree at tag `lib/ministral-ee89587` (`anatta-dev/src/anatta`); main is `src/anatta` at 27480ad
plus this step's changes. Everything here ran on the laptop CPU, parse-only, at no cost.

**Headline.** Main is a strict superset of the pin, apart from two behaviour changes. Both are now named options,
so finished experiments keep their numbers.
- The koan release rule has three parsers: `main`, `instrument-v2` and `pin-ee89587`.
- HFPolicy's reseeding has two rules: `per-call` and `pin-ee89587`.

h4lite's Commons runs were graded under instrument v2 (`harness_v2.apply()`), which now selects
`instrument-v2`. Re-graded from the stored replies, `instrument-v2` and main's default parser disagree on 6
distinct assistant replies, all in `fishery/lie1`. Everything else is identical. The coding-koan runs use koan_env's
own strict rule and don't depend on the library parser. Nothing recorded was re-graded in place.

## 2. The two behaviour changes, and how finished results stay reproducible

### Koan release parser (`anatta.koans.base`)

There were three rules in use, not two. Instrument v2 (`lab/experiments/recognition/scripts/harness_v2.py`, 29 Oct)
patched the pin's `released()` with its own action pattern, `<harvest>|<take>|<report>|```. Main's built-in
pattern is `<run>|<harvest>|<report>|```. They differ on `<take>` (the lie-block game's move) and `<run>`.

| Parser | A `<release>` counts unless the reply has | Used by |
|---|---|---|
| `main` (default) | `<run>`, `<harvest>`, `<report>`, a code fence | new work |
| `instrument-v2` | `<harvest>`, `<take>`, `<report>`, a code fence | h4lite's Commons runs (records say `"instrument": "v2"`); recognition `v2_*`; `modal_coding_eval` hand-written twins |
| `pin-ee89587` | nothing: any `<release>` counts | recognition runs before v2; the pinned library |

Selecting one: `set_release_parser(name)` (process-wide, returns the previous one), or `released(reply, parser=name)`.

`harness_v2.apply()` now calls `set_release_parser("instrument-v2")` on main, and patches nothing else. Main's
default reseed is already v2's rule 2, so patching HFPolicy as well would have reseeded twice. Under the pin (no
`set_release_parser`) it patches as before. `fishery_grade.py` keeps its own verbatim copy of the v2 rule;
`test_fishery_grade.py` checks it against `harness_v2`.

### HFPolicy reseed (`anatta.bench.policies`)

`HFPolicy(..., reseed="per-call")` is the default. `reseed="pin-ee89587"` restores the pin's `manual_seed(seed)` on
every call. Instrument v2's per-turn seed (`seed*1000 + turn`) equals main's `per-call`, so h4lite's Commons runs
replay identically under main with `harness_v2.apply()`. Sampling can't be re-graded parse-only: a run that used the
pin's rule (recognition `cut_vs_push` without `ANATTA_V2`) reproduces only with `reseed="pin-ee89587"` and the same
GPU stack, or at the old tag.

lab/explore/bench samples through its own `steering.Service`, not HFPolicy, so no stored bench output depends on
either change. act1 grades through koan_env's strict rule.

## 3. Re-grade deltas (stored data, parse-only)

Tool: `lab/tools/regrade_release.py` (counts only; never prints a reply, never runs anything). It takes every string
holding `<release>` in every .json/.jsonl, prompts included, and counts how many each parser calls a release. Totals:

| Store | Tagged strings | pin | instrument-v2 | main | v2 ≠ main (distinct) | pin ≠ main (distinct) |
|---|---|---|---|---|---|---|
| `lab/experiments/h4lite/results` (96 folders) | 110,884 | 110,884 | 71,404 | 71,420 | **6** | 25,384 |
| `lab/experiments/recognition/results` (65 folders) | 41,206 | 41,206 | 25,602 | 25,606 | **4** | 6,352 |
| `results_root/explore` | tags only in bench prompts (lead1, lead7) | | | | n/a: no explore grader calls `released()` | |

- **h4lite, graded under instrument v2** (fishery/*, audit_dose, hub_cut, third_person, restoring_force,
  self_tests). The only v2 ≠ main disagreements are in `fishery/lie1`. They are 6 distinct assistant turns that make
  a `<take>` move and also hold a `<release>`: 5 in the `base.off` pool and 1 in `base.cut_self_stakes_17_26`.
  - v2 (what lie1 was graded with) scores each as the move; main's default would score each as a release.
  - A release changes the game from that season on (harvest 0, co-fishers mirror it), so the game numbers can't be
    recomputed parse-only. Under main's default, lie1 would *not* reproduce. Under `instrument-v2` it does, by
    construction.
- **h4lite coding koans** (gate0, sft, heldout, retreat2, durability, declared). These were graded by koan_env's
  `strict_release` (one closed tag, no code, nothing after it), which doesn't read the library parser, so step 2
  changes none of their numbers. The large pin ≠ main counts there are information only.
- **recognition.** `r1m_pool` holds 4 v2 ≠ main replies (2 distinct, plus their chunk copies). The pre-v2 folders
  (cut_controls, cut_vs_push*, dig_*, rep_*, r1m_*) were graded under the pin's loose rule, and main differs from it
  on hundreds of replies per folder. The recognition scripts stay on the pin (their run lines set
  `PYTHONPATH=anatta-dev/src`) and reproduce at tag `lib/ministral-ee89587`.

The flipped replies' sha256 come out with `--json OUT`.

## 4. What moved to main's library

- **bench** (`lab/explore/bench`): `client.py` no longer puts anatta-dev on sys.path. `controls.py` reads main's
  trait YAMLs (byte-identical to the pin's). The test conftest drops anatta-dev.
- **h4lite**:
  - The Modal images in `modal_common.py` and `h4_modal.py` mount main's `src/` (same path inside and outside,
    as anatta-dev's was).
  - `koan_pairs.py`, `lcb_loader.py` and `positive_control_adapter.py` drop their anatta-dev inserts.
  - `declared_core.fingerprints` hashes `anatta/{models,koans/base,koans/impossible}.py` from the imported
    package. These are information-only shas: a re-freeze records main's.
  - Every run line and `.sh` sets `PYTHONPATH=<repo>/src`.
- **selfmap, act1**: they reached the pin only through `modal_common.image`, which now mounts main.
- **p1**: `ANATTA_SRC` is main's `src/` (mounted at `/root/anatta_src`). Two more fixes:
  - `ensure_paths` no longer adds it.
  - `save_controls` looks for a saved control under both names: the target's tensor hash, which bench's
    `save_control` has used since 1 Nov, and the file hash that P1's first run used. Before this fix a rebuild
    never reused a control file and wrote a new one each time.
- **scout**: `spend.py`'s `_anatta_main` bridge loader is gone; it imports `anatta.spend`.
- **player.py**: one implementation, `src/anatta/player.py`.
  - Main's copy was already a superset of h4lite's: `alpha` and `use_rslora` on `attach_adapters`, with the same
    defaults, and `ENV_ERROR` and `first_failed` equal to pilot.py's.
  - `lab/experiments/h4lite/player.py` is now a shim: `import player` returns `anatta.player` itself, so tests that
    patch `player.X` patch what the apps call.
  - The shim registers `"koan_env"` in `anatta.player.ENV_ERROR_MODULES`, so `safe_step` also catches that copy's
    `EnvError`, looked up at call time as the old copy's lazy import did. This lasts until the copy is retired in
    step 7.
  - The old file is `archive/h4lite/player.py`.
  - C3's and C7's run fingerprints record `player.py`'s sha per run (not a registered pin), so their next runs will
    record the new sha.

Note: the Modal CLI venv (lab.toml `modal.cli`) has no anatta installed. Local entrypoints run from it need
`PYTHONPATH=<repo>/src`, as they needed anatta-dev's before. The in-code anatta-dev inserts used to hide this.

## 5. Not moved, and why

- **calibration/** (frozen). `koan_scorer/{app,card}.py` read anatta-dev's `koans/base.py` to record its sha and
  compare `CODE_RE` (`CODE_RE` is identical in main). `k7_agentic/app_hf.py` names anatta-dev in a docstring.
  `tests/test_koan_scorer.py` (`DEV_BASE`) and `lab/experiments/h4lite/c6_samples.py` (`--anatta-dev`, recording
  what the lab imported for C6) need anatta-dev to exist: they will skip or need the old tag once anatta-dev is
  archived.
- **C4 (persona_extractor) fails on main, and has since 1 Nov.** Its config registers `src/anatta/models.py` at
  sha256 `99d3a916…`, the pin's bytes. Main's models.py gained the additive helpers on 1 Nov, so `make_plan`
  refuses, and 16 of its tests fail (the same 16 before and after this step). Lead's decision: re-register C4's
  instrument on main's models.py, or run C4 only at the old tag.
- **recognition/** stays on the pin, as above. Only `harness_v2.py` changed, so it works on both libraries.
- `noself/modal_noself3.py`: a recorded source string about a finished run.
- `tools/guard.py` and `tests/test_guard.py`: the guard's read-only rule for anatta-dev, kept while the worktree
  exists.
